# StockTest 多源证据盘后分析设计

## 1. 目标

把首页硬编码的“市场状态”和“盘后摘要”替换为每天美股收盘确认后生成一次的、可追溯的研究型市场判断。

系统必须满足：

- 数值规则决定市场状态和因子分数，AI 不得覆盖规则分数；
- 每条事实和推断都能追溯到结构化证据；
- 没有证据的内容不得作为事实显示；
- X 只作为人工加入的市场线索，不是唯一来源，也不直接影响评分；
- 浏览器只读取本地 JSON，不直接访问外部数据源；
- 当前阶段不恢复主题 Top 20、独立基本面页面或小程序。

## 2. 实施范围

### 第一阶段：可运行的确定性证据引擎

复用现有 `market_snapshot.json`、`stockbee.json` 和 `refresh_status.json`，生成新的 `market_analysis.json`。它包含五项因子、综合状态、研究摘要、观察项、数据质量和全部证据引用。

第一阶段只使用已经接入并验证过的数据：

- Yahoo Chart：美股指数、板块 ETF 和行业 ETF 完整日线；
- Binance：BTC 日线；
- Stockbee Market Monitor：最近 20 日、15 个原始宽度指标；
- 本地刷新状态和行情质量报告。

第一阶段不伪造事件、新闻或社交证据。没有外部事件证据时，页面明确显示“当前结论仅基于市场数据与宽度数据”。

### 第二阶段：官方一手来源

在不改变 `market_analysis.json` 消费接口的前提下，按需增加：

- SEC EDGAR：8-K、10-Q、10-K 和 Company Facts；
- Federal Reserve：新闻稿、FOMC、讲话和利率资料；
- BLS：CPI、PPI、就业和工资数据；
- BEA：GDP、PCE、企业利润和行业数据；
- U.S. Treasury：国债收益率、拍卖及财政数据；
- ETF 发行商：官方持仓、行业权重和持仓日期。

### 第三阶段：公开媒体与社交线索

- 公开媒体只保存标题、发布时间、简短摘要和原始链接，不保存全文；
- 同一事件优先用官方来源验证，媒体用于解释市场如何解读；
- X 使用可信账户白名单和手工加入的 Post URL；
- 未获一手资料验证的媒体或 X 内容只能标记为 `lead`，不得进入评分。

## 3. 总体架构

```text
market_snapshot.json ─┐
stockbee.json         ├─> market_analysis.py ─> market_analysis.json ─> app.js
refresh_status.json   │          │                       │
quality report        ┘          ├─ 因子评分              ├─ 市场状态卡
source registry  ────────────────└─ 证据校验              ├─ 盘后摘要
                                                       └─ 证据抽屉
```

新增单一分析模块 `data_pipeline/market_analysis.py`，职责只有四项：

1. 从现有快照提取同一美股收盘日的可比指标；
2. 根据固定规则计算五项因子和综合状态；
3. 生成事实、推断、观察项与证据引用；
4. 校验后原子写入 `data/market_analysis.json`。

刷新器在行情与 Stockbee 刷新完成后调用分析模块。分析失败不得覆盖上一份成功结果，并把结果写入 `refresh_status.json` 的 `sources.analysis`；网页继续显示旧分析且标记过期。

## 4. 数据模型

### 4.1 SourceRecord

```json
{
  "id": "stockbee-market-monitor",
  "name": "Stockbee Market Monitor",
  "category": "market-breadth",
  "tier": 1,
  "mode": "automatic",
  "url": "https://stockbee.blogspot.com/p/mm.html",
  "enabled": true,
  "affectsScore": true
}
```

`tier` 取值：

- `1`：原始行情、官方统计、监管文件、公司或 ETF 官方披露；
- `2`：可公开访问的主流媒体，用于交叉验证和解释；
- `3`：X 等社交线索，只能作为 `lead`。

来源白名单保存在 `data/source_registry.json`。未在白名单中的来源不能进入正式分析。

### 4.2 Evidence

```json
{
  "id": "breadth-2026-08-28-ratio5",
  "sourceId": "stockbee-market-monitor",
  "type": "metric",
  "asOf": "2026-08-28",
  "label": "5 日上涨／下跌比",
  "value": 0.98,
  "unit": "ratio",
  "direction": "neutral",
  "sourceUrl": "https://stockbee.blogspot.com/p/mm.html",
  "capturedAt": "2026-08-30T09:51:55Z",
  "quality": "confirmed"
}
```

`quality` 只允许 `confirmed`、`stale`、`partial`、`lead`。证据 ID 在一个分析文件中必须唯一。

### 4.3 Claim

```json
{
  "id": "claim-breadth-not-confirming",
  "kind": "inference",
  "text": "市场宽度未确认指数强势。",
  "confidence": 0.82,
  "evidenceIds": [
    "breadth-2026-08-28-ratio5",
    "breadth-2026-08-28-up-down"
  ]
}
```

`kind` 只允许：

- `fact`：证据直接表达的事实；
- `inference`：由多个事实推导的解释；
- `scenario`：带条件的可能路径；
- `watch`：下一交易日需观察的验证项；
- `lead`：尚未被一手来源验证的媒体或社交线索。

`fact`、`inference` 和 `scenario` 至少引用一条非 `lead` 证据。`lead` 不得出现在综合评分或正式摘要前三条中。

### 4.4 MarketAnalysis

```json
{
  "schemaVersion": "1.0",
  "analysisId": "us-close-2026-08-28",
  "asOf": "2026-08-28",
  "generatedAt": "2026-08-30T10:00:00Z",
  "mode": "rules-only",
  "state": "震荡",
  "score": 0,
  "confidence": 0.82,
  "headline": "指数企稳，但内部宽度仍未确认。",
  "summary": "市场维持震荡结构，板块轮动快于整体扩散。",
  "factors": [],
  "briefing": [],
  "watchNext": [],
  "evidence": [],
  "dataQuality": {},
  "provenance": {}
}
```

## 5. 五项因子与评分

每项因子取 `-2`、`-1`、`0`、`+1`、`+2`。综合分等于五项相加，范围 `-10..+10`，不再使用缺少数据依据的“流动性”。

### 5.1 趋势

使用 SPX、NDX、DJI、RUT 在分析日的 5 日和 20 日收益：

- 四个指数的 5 日与 20 日收益全部为正：`+2`；
- 至少六个值为正：`+1`；
- 正值数量为三至五：`0`；
- 正值数量为一至二：`-1`；
- 全部非正：`-2`。

### 5.2 宽度

使用 Stockbee 最新行的 `ratio5`、`ratio10`、`up`、`down` 和 `t2108`：

- `ratio5 >= 1.5`、`ratio10 >= 1.25`、`up > down`、`t2108 >= 55` 中满足四项：`+2`；
- 满足三项：`+1`；满足两项：`0`；满足一项：`-1`；全部不满足：`-2`。

### 5.3 动量

以 12 个传统板块/风格 ETF（14 行板块表剔除 SPY 与 IBIT）和 60 个行业 ETF 的 RSI14、5 日和 20 日收益计算；IBIT 只进入风险偏好因子：

- 板块与行业中 `RSI14 >= 60` 且 20 日收益为正的比例；
- 比例 `>= 60%` 为 `+2`，`>= 45%` 为 `+1`，`30%..45%` 为 `0`，`15%..30%` 为 `-1`，低于 `15%` 为 `-2`。

### 5.4 轮动

防御组为 `XLU/XLP/XLV`，成长组为 `XLK/XLY/XLC/ARKK`。比较两组相对 SPY 的平均 5 日收益：

- 成长领先超过 2 个百分点：`+2`；
- 成长领先 0.5 至 2 个百分点：`+1`；
- 差值在正负 0.5 个百分点内：`0`；
- 防御领先 0.5 至 2 个百分点：`-1`；
- 防御领先超过 2 个百分点：`-2`。

该分数表达风险风格，不把“防御领先”误写成市场必然下跌。

### 5.5 风险偏好

在统一的美股分析日比较 `RUT-SPX`、`IBIT-SPY` 和 BTC 同日收益：

- 三项均正：`+2`；两项正：`+1`；一项正：`0`；全部非正：`-2`；
- 当 BTC 缺少同日数据时，只使用前两项，分别映射为 `+1/0/-1`，并降低置信度。

BTC 周末数据不能倒灌到周五美股正式分析。

### 5.6 综合状态

- `+7..+10`：强势上涨；
- `+3..+6`：偏强；
- `-2..+2`：震荡；
- `-6..-3`：偏弱；
- `-10..-7`：下跌。

## 6. 置信度与数据质量

基础置信度为 `1.0`，按以下规则扣减：

- 行情快照存在缺失标的：每个扣 `0.02`，最多扣 `0.20`；
- Stockbee 最新日期早于美股分析日超过一个美股交易日：扣 `0.20`；
- 刷新状态为 `partial`：扣 `0.10`；为 `failed`：扣 `0.25`；
- 某因子因数据不足无法计算：每项扣 `0.12`；
- BTC 缺少统一分析日数据：扣 `0.04`。

最终置信度限制在 `0.30..1.00`。低于 `0.60` 时页面显示“低置信度”，摘要不得使用“确认”“明确”等强确定性措辞。

## 7. 摘要生成规则

第一阶段不调用生成式模型，使用确定性模板生成研究摘要：

- 标题由综合状态与最低/最高因子组合；
- 摘要说明指数趋势、内部宽度与轮动是否一致；
- `briefing` 固定最多三条：最强证据、最大分歧、主要风险；
- `watchNext` 固定最多三条，必须写成可验证条件；
- 每一项都携带 `claimId` 和 `evidenceIds`。

第二、三阶段可让 AI 把已验证 Claim 改写成更自然的中文，但 AI 只能引用输入中的 Claim 和 Evidence，不能新增数字、事件、公司、来源或分数。AI 输出未通过校验时自动回退到确定性模板。

## 8. 页面行为

首页保留现有布局，精准替换内容：

- 主卡片显示状态、综合分、置信度、分析日期和一句核心判断；
- 因子标签改为趋势、宽度、动量、轮动、风险偏好；
- 盘后摘要三条由 `market_analysis.json` 驱动；
- 每条摘要显示来源数量；
- 增加“查看全部依据”按钮，打开右侧证据抽屉；
- 抽屉按结论分组展示证据值、日期、来源、质量状态和可点击原始链接；
- `rules-only` 模式显示“仅市场数据”，未来接入官方事件后显示“市场数据 + 官方事件”；
- 分析文件缺失或校验失败时显示“分析暂不可用”，不回退到当前硬编码结论。

键盘要求：按钮可聚焦，Enter/Space 打开抽屉，Escape 关闭，关闭后焦点返回触发按钮。

## 9. 来源白名单初始内容

第一阶段启用：

- `yahoo-chart`，tier 1，自动，影响评分；
- `binance-public-klines`，tier 1，自动，影响风险偏好评分；
- `stockbee-market-monitor`，tier 1，自动，影响宽度评分；
- `stocktest-quality-report`，tier 1，自动，只影响置信度。

第二阶段先登记但禁用：

- `sec-edgar`、`federal-reserve`、`bls-public-data`、`bea-api`、`us-treasury-fiscal-data`；
- `ssga-holdings`、`ishares-holdings`、`vanguard-holdings`。

第三阶段来源必须逐个加入白名单。不存在“任意网页均可信”的通配来源。

## 10. 失败与降级

- 输入校验失败：不生成新文件，保留上一份成功分析；
- 分析日早于当前正式美股收盘日：页面显示“分析过期”；
- 单项因子失败：因子标记 `unavailable`，不以 `0` 冒充中性；
- 来源不在白名单：拒绝该证据并记录错误；
- Claim 引用不存在的证据：整个输出校验失败；
- AI 改写增加未知数字或来源：拒绝 AI 输出并显示规则模板；
- 外部链接只允许 `https://`，页面使用安全的新窗口打开方式。

## 11. 测试与验收

### 数据测试

- 五项因子在边界值上的评分正确；
- BTC 使用与美股相同的 `asOf`，不使用周末未来数据；
- 每个 Claim 的证据引用存在且来源在白名单；
- `lead` 不影响分数，也不能进入正式摘要前三条；
- 缺失和过期输入正确降低置信度；
- 分析失败不覆盖上一份成功文件；
- 同一输入重复运行产生相同的分数、状态和 Claim 内容。

### 页面测试

- 页面不再包含硬编码市场状态和摘要；
- 分析卡、因子和三条摘要均来自本地分析文件；
- 证据抽屉可打开、关闭、键盘操作并返回焦点；
- 每条正式结论至少显示一个来源；
- 缺失、过期和低置信度状态可见；
- 1440、1024、768 和 390 宽度无不可达操作；
- 浏览器控制台错误为 0。

## 12. 非目标

- 不提供买入、卖出、仓位或目标价建议；
- 不把相关性描述成确定因果；
- 不在第一阶段抓取新闻、X 或付费数据；
- 不安装数据库、任务队列或前端框架；
- 不更改现有行情、Stockbee、板块、行业、持仓和宽度组件；
- 不修改 `sources/`。

## 13. 完成定义

第一阶段完成必须同时满足：

1. 本地刷新后生成通过校验的 `market_analysis.json`；
2. 首页市场卡和盘后摘要全部由该文件驱动；
3. 任一结论可在证据抽屉中追溯到数值、日期和来源；
4. 所有现有测试与新增测试通过；
5. JavaScript 语法、HTTP、响应式和控制台验证通过；
6. `PROJECT_PROGRESS.md` 只新增一条本阶段记录，不创建重复进度文档。
